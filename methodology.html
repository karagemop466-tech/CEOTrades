Methodology & verification

Where the data comes from, what it includes, and every check that runs before it is published. Nothing on this site is estimated — every number traces to a specific SEC filing.

What is collected

  • All Form 4 filings in the data window — every Section 16 report of insider holdings changes for officers, directors and 10% owners of public companies.
  • Every transaction line: Table I (equity: common stock, etc.) and Table II (derivatives: options, warrants, convertible securities).
  • Filing metadata: issuer, reporting person, relationship, transaction code, dates, shares, per-share price, post-transaction holdings, footnotes, and the Rule 10b5-1(c) flag.

What is not included

  • Form 3 (initial holdings), Form 5 (annual), Form 144 (intent to sell), Schedule 13D/G.
  • Amendments to earlier Form 4s are included as filed — a single security can therefore appear in both the original and the amendment.
  • Holdings-only filings (a Form 4 that reports no transaction) are counted as parsed filings but contribute no transaction rows.
  • If a filing cannot be parsed, it is listed below — never silently dropped.

Pipeline

  1. Enumerate. Query SEC's EDGAR full-text search for every Form 4 filed each day of the window (fallback: EDGAR daily index). The index reports the expected total; a mismatch fails the run.
  2. Download. Fetch each filing's machine-readable ownershipDocument XML from www.sec.gov/Archives/edgar/data/….
  3. Parse. Extract issuer, reporting person, relationship, and every transaction with shares, price, code, dates and footnotes.
  4. Aggregate. Compute daily activity, type/role/company/sector groupings directly from the parsed records.
  5. Validate. Independent re-computation of every summary number from the raw transaction list (see below).
  6. Verify. Re-download a random sample of the published records from SEC and confirm each one line by line (see below).

Validation (offline checks)

Every record is checked for format, uniqueness, value arithmetic (value = shares × price), and every aggregate is recomputed independently from the transaction list.

    Live verification (SEC cross-check)

    A deterministic random sample of records is re-downloaded from SEC EDGAR and re-parsed; issuer CIK, owner CIK, period and the exact transaction row must match what the dashboard publishes.

    How value and shares are defined

    • Value is computed as shares × per-share price exactly as the filer reported them (U.S. dollars, per Form 4 Instruction 5). It is not a market valuation and excludes commissions.
    • Derivative transactions (options, warrants, units) are shown separately; their "value" is not computed because the derivative security's price is often blank (Instruction 4(c)(iii)).
    • Shares are the reported amounts; the site never adjusts for stock splits or reverse splits.
    • Footnotes accompany the affected cells (hover the shares/price cell on the trades page).
    Caveats

    Data is reported as filed and may be corrected by amendments. Prices are per-share prices as reported, which for some transactions (e.g. gifts, grants) may be 0 or blank even though the security has value.
